## Rework triage

- **Type: implementation error.** The requirement has not changed — `PRD-21798.md`'s
  BA-gated Scope/Done-when (line 18: "the reporter's fixture ... returns the
  exception text and `hadErrors: true`; a clean script returns `hadErrors: false`")
  still stands and is not being reopened. What failed is the shipped
  implementation's field-name guess, which round 1 explicitly flagged as an
  unverified assumption (round-1 doc, Open questions, "This is a guess, explicitly
  flagged as such") and which this round's QA run proves wrong.
- **Evidence**: comment `#1600390000061190` (dev01, 2026-11-10 08:18Z),
  `[QA-NIGHT] FAIL on INT (QA run #297, 6/7) — back to groom`. Deployed code:
  `MSPbotsAIFramework/immybot-mcp` `main` @ `ce150a2` (merged from `dev/PRD-21798`,
  published to INT 2026-11-05). Live run `add42035-7795-46ac-b529-2c8591f23d22` on
  test machine DEV-W11-01, Local script 2 ("MSPbots test - error"), returned
  `{"status":"Completed","output":["TEST-ERR DEV-W11-01"],"hadErrors":false}` with
  no `errors` key — i.e. none of round 1's `_ERROR_FIELDS` candidates
  (`error`, `errorOutput`, `exceptionMessage`, `exception`, `scripts.py:70`)
  matched the real field on this live instance. The same comment reports the
  clean-run case (script 1, run `1a015458-2122-45f3-8e27-1e64d9f8e8f7`) still
  correctly returning `hadErrors: false` — "weak evidence given TC2" per the
  reporter, since a clean run returning no error is not very informative on its own.
- **What this round changes**: nothing in Product design (Goals/Non-goals/AC1-AC4
  are unchanged and still correct — AC1 was never met, which is exactly what QA
  found) and nothing in Tech design's chosen approach (round 1's Risks section
  already named this exact failure mode and already instructed "must report the
  real field/shape as evidence ... updating the implementation in the same
  ticket" — `PRD-21798.md:150`). This round adds one thing: **TC8**, a regression
  test case pinned to the concrete QA-NIGHT evidence above (appended to
  `PRD-21798.ac.json`, `dw: DW1`, `result: fail`) so the next dev leg has a
  falsifiable target tied to a real run id, not a re-statement of the same
  "needs a real vendor account" hand-wave that shipped last time. TC1-TC7 are
  unchanged (per `legs/design/rework.md`, an implementation-error rework does not
  edit existing cases); all seven also gained a `dw` field they did not have in
  round 1 (added 2026-11-09, after round 1 was written — `DW1` for the error-path
  cases (TC1/TC2/TC5/TC6/TC7), `DW2` for the clean-path cases (TC3/TC4), per the
  BA Scope/Done-when quoted above).
- **Why TC2 itself is not edited**: `legs/design/rework.md` forbids changing an
  existing case's text/steps/expect/result for an implementation-error rework.
  TC2 still reads `result: "untested · needs a real vendor account"`, which is
  stale now that QA-NIGHT did execute the equivalent call live and it failed —
  but that staleness is exactly what TC8 is for: TC8 is the dated, evidenced
  record of what actually happened; TC2 stays as round 1 left it.
- **What this round does not do**: it does not pick a replacement field name or
  a new detection strategy. The comment's own suggested fix ("read the instance's
  `/swagger/v1/swagger.json` or a real `adhoc-script-runs` record to find the real
  field") needs a live call against `mspbotsai.immy.bot`; this design environment
  still has no ImmyBot credentials (checked again this round: no `IMMY_*` env
  vars; `curl https://mspbotsai.immy.bot/swagger/v1/swagger.json` unauthenticated
  returns `401 PrincipalMissing`) — the same gap round 1 hit, now with proof it
  matters. Picking the actual fix (which field, or a more general detection
  mechanism such as scanning every key on the row for an error-shaped name
  instead of a fixed whitelist) is dev leg's tech-design call, same as it has
  always been for implementation details that don't change user-visible
  behavior (`SKILL.md`'s "three artifacts" ownership table: dev may change the
  tech design freely as long as user-visible behavior is untouched).
